# Signature Elements

A functional design can have expressive elements. An app may have one or two signature elements that come from its domain. Examples are a printed badge, a paper repair tag, a ticket stub, a shipping label, and a receipt.

## Part Of The Design

- Treat a signature element as part of the design, not as decoration that you can remove.
- A rule set must not forbid signature elements. When a general rule, such as the rule on [[edge-accents]], blocks a shaped edge that makes the element look like the real thing, the signature element is permitted.
- The element must still follow the hierarchy of the page.

## Tie It To The Domain

- Tie each signature element to a real thing in the domain.
- Do not invent an ornament that has no meaning for the user.

## Build It From Tokens

- Build the element in the app from the design tokens: colors, type, spacing, radii, and shadows.
- A shaped edge, a slight rotation, a punched hole, or a paper texture is permitted when it makes the element look like the real thing.

## Keep The Semantics

- Real text stays text.
- The element has an accessible name.
- The meaning does not depend on color only.
- A shaped edge must not mark selection or the current navigation item.

## Placement

- Put the element where it carries meaning, such as the preview of the end result. [[form-preview]] gives the rules.
- Do not repeat it on every page.
