# Form Layout

The layout of a form shows its structure before people read a label.

## Sections

- Group fields by user intent, not by storage structure.
- Put related fields into named sections, such as profile, account, billing, or notifications.
- Add section guidance only when it helps users understand the requested information.

## Title Column

- In a long form, put each section title and one sentence about what the answers change in a column beside the fields.
- On narrow screens, stack the column above the fields.
- A title or guidance column can balance unused width on large screens.

## Width

- Do not stretch every input across the page. [[form-fields#size-and-length]] gives the input sizes.

## Control Surfaces

- Make a clear surface difference between controls and the page. White controls on a subtle off-white page are one option.
- Put related read-only values in a quiet inset surface. [[depth#inset-and-raised-surfaces]] gives the rule.

## Footer

- Keep the primary action of a long form in view, in a footer that stays at the bottom of the window.
- Put a short live summary, such as a count or an estimate, in the same footer.
- Place the workflow actions as in the rest of the product. [[hierarchy#actions]] gives the rules.
